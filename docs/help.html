XSwitch 使用帮助

XSwitch 是一款基于 Manifest V3 declarativeNetRequest 的 Chrome 请求转发插件：把线上资源代理到本地服务、注入调试请求头、处理 CORS 跨域，让本地开发更轻松。

🏠 项目主页（源码 / 反馈 / 更新记录）：github.com/laomu1024/xswitch

Manifest V3 JSONC 注释支持 Monaco 编辑器 规则分组 内置在线 Demo

01简介

日常前端开发中，经常需要把 CDN 或线上接口的资源指向本地：改一行线上 JS 立刻用本地文件调试、让跨域接口直通 mock 服务、给请求附加调试 Header。XSwitch 通过一组 JSON 规则描述这些改写，插件会把规则编译成浏览器原生的 DNR 动态规则，在不发代理、不改 hosts 的情况下完成 URL 重定向与头部修改。

🔀URL 重定向

整条精确替换、捕获组片段替换、inline JS（data: 协议）三种模式。

🌐CORS 跨域

声明需要跨域的链接，自动为响应设置 Access-Control 头。

📝请求头注入

headers 规则只加头不改地址，适合打标、切环境。

🗂分组管理

多套配置随时勾选组合，按顺序合并执行。

03规则基础结构

每个规则条目都是一个 JSONC 对象，最多包含三个顶层字段：proxy（转发）、cors（跨域）、headers（请求头注入）。字段均可省略，只写用到的部分。

// 当前编辑条目的规则（// 开头是注释，不会参与匹配）
{
  "proxy":  [ ["匹配到的地址", "替换后的地址"], ... ],
  "cors":   [ "需要跨域的地址", ... ],
  "headers": [ ["匹配到的地址", { "头名": "头值" }], ... ]
}

proxy 的每条规则是一个二元数组：第 1 项是「匹配模式」，第 2 项是「替换目标」。插件会把配置编译成浏览器原生的 DNR 规则，不同字段的匹配语义有所不同：

字段底层匹配形式匹配语义
proxy / headersRE2 正则（regexFilter）正则必须匹配整条 URL（隐式全匹配），默认不区分大小写
corsURL 匹配模式（urlFilter）URL 包含该子串即命中，* 为任意通配；不支持正则，. ( ) 等按字面处理
  • 整条 URL 匹配：模式里写一条完整 URL（如 https://a.com/x.js），只有请求 URL 与它完全一致才命中；要覆盖某域名下的所有路径，需要补 /(.*) 之类的尾部。
  • 替换目标 = 全新 URL：转发后的地址由「目标」整串重建，原 URL 中没有被捕获组引用的部分会丢失，需要保留时要用 (.*) 捕获、目标里用 $1、$2 引用。
  • RE2 限制：不支持先行断言 (?=、后行断言 (?<! 等语法；不合法的规则会被浏览器拒绝。
  • 适用资源类型：页面（主框架/子框架）、XHR/fetch、脚本、样式表、图片、字体、其他；WebSocket、媒体类请求不适用。
想让 .、?、+ 在 proxy/headers 模式中按字面匹配时，请写成 \.、\?、\+；它们默认都是正则量词。cors 字段则相反——按字面处理，不是正则。

04proxy 转发规则

模式 1整条 URL 精确替换 —— 一条 URL 换另一条 URL

模式写完整地址时，只有请求 URL 与它完全一致才命中（URL 带查询参数就不会命中），常用于把某个固定文件指到别处。

"proxy": [
  [
    "https://unpkg.com/react@16.4.1/umd/react.production.min.js",
    "https://unpkg.com/react@16.4.1/umd/react.development.js"
  ]
]

模式 2URL 局部片段替换 —— 换掉地址中的一段、保留其余

要替换 URL 中间的片段（如整域名切换），模式必须用 (.*) 覆盖整条 URL 并把保留部分捕获，目标里再用 $1、$2 拼回，否则未引用的片段会丢失。

"proxy": [
  // 把 URL 里所有的 alinw 换成 g，其余部分原样保留
  ["(.*)alinw(.*)", "$1g$2"],
  // 接口域名整体切到本地 mock，保留路径
  ["https://api.real.com/(.*)", "http://127.0.0.1:9000/$1"]
]

模式 3正则替换 —— 捕获组复用

替换目标里用 $1、$2 引用第 1、2 个捕获组（按 JS String.replace 语义书写即可，插件会自动转换成 DNR 要求的 \1 语法）。

"proxy": [
  // https://www.sample.com/path1/path2/index.js → http://127.0.0.1:3000/index.js
  [
    "(.*)/path1/path2/(.*)",
    "http://127.0.0.1:3000/$2"
  ]
]

模式 4inline JS —— 直接返回一段代码内容

目标写成 data: 协议 URL 时，请求不落地到任何服务器，而是直接返回编码在里面的内容，可用来打桩。

"proxy": [
  [
    "https://alinw.alicdn.com/platform/daily-test/isDaily.js",
    "data:text/javascript,window.__isDaily = true;"
  ]
]
把 HTTPS 资源转发到本地时，推荐写 http://127.0.0.1:端口 而不是 localhost，浏览器不会出安全提示。

05cors 跨域规则

把需要跨域访问的接口地址写进 cors 数组，命中的响应会被设置为四个跨域响应头：Access-Control-Allow-Origin: *、Access-Control-Allow-Methods、Access-Control-Allow-Headers: *、Access-Control-Allow-Credentials: true。

"cors": [
  "mocks.a.com",      // 子串：URL 包含即命中
  "*.b.com",          // * 通配：任意前缀的 b.com
  "127.0.0.1:9000"     // 本地 mock 服务
]
  • 数组项是 URL 匹配模式，不是正则：URL 包含该项即命中，* 表示任意长度通配；.、(、) 等按字面处理，(.*).b.com 这类正则写法在这里无效，要匹配子域请直接写 *.b.com。
  • DNR 静态规则只能注入固定值，Access-Control-Allow-Origin 只能是 *；携带凭据（withCredentials）的跨域请求遇到 * 仍会被浏览器拦截，这是 Manifest V3 的平台限制。此类场景建议用 proxy 把接口转发到与页面同源（或本地）的地址。
  • 面板上的 CORS 开关用于单独启停这部分行为，不影响 proxy 转发。

06headers 请求头规则

格式为 [匹配模式, 头键值对象]：命中请求时注入/修改指定请求头，不改变 URL。匹配模式与 proxy 相同，是整条 URL 全匹配的 RE2 正则，因此覆盖域名下所有路径要补尾部。

"headers": [
  // 命中 api.example.com 下所有路径（含根路径）
  [
    "https://api.example.com(/.*)?",
    { "X-Debug": "1", "X-Env": "local" }
  ],
  // 也支持捕获组等任意合法正则
  [
    "(https://img.a.com)/v2/(.*)",
    { "X-Canary": "1" }
  ]
]
  • 同名请求头已存在时会被覆盖（set 语义）。
  • 头值允许数字、布尔，会自动转成字符串；值为 null/undefined 的项和空对象会被跳过。
Host、Content-Length 等浏览器保留头无法修改，这是浏览器安全限制，并非插件缺陷。

07执行顺序与分组

  • 一个请求只会命中一条规则：浏览器对每个请求只应用单条匹配规则，不会链式改写（与早期 MV2 版本不同）。既要换域名又要改路径时，请合并进一条规则用捕获组一次完成，不要依赖两条规则接力。
  • 避免规则重叠：多条规则的模式都能匹配同一请求时，最终生效哪条由浏览器决定且可能随版本变化。列表顺序决定规则的生成顺序，但请把互斥写清楚，而不是依赖顺序压过另一条。
  • 分组叠加：左侧列表中每个条目可独立勾选，所有分组地位相同。多个分组同时勾选时，按列表顺序把各自的 proxy / cors / headers 依次拼接后一起编译生效。
  • Pin 只影响展示：置顶常用配置只调整列表展示顺序，不改变规则的实际执行顺序。
  • 全局开关优先级最高：关闭总开关后，任何分组的勾选都不再生效。

08完整示例

一个典型的「本地调试线上页面」配置：CDN 的 JS/CSS 指向本地 dev server，接口直通 mock 并放开跨域，同时给接口打上环境标。

{
  "proxy": [
    // 1. 线上 CDN 目录 → 本地构建产物目录（正则 + 捕获组）
    [
      "(.*)/cdn/my-app/(.*)/pages/(.*)",
      "http://127.0.0.1:8080/pages/$3"
    ],
    // 2. 单个文件精确替换（请求 URL 需与之完全一致，不带查询参数）
    [
      "https://g.alicdn.com/lib/config.js",
      "http://127.0.0.1:8080/mock/config.js"
    ],
    // 3. 接口域名整体切到 mock 服务，用 $1 保留原路径
    ["https://api.real.com/(.*)", "http://127.0.0.1:9000/$1"],
    // 4. inline 打桩：直接返回一段 JS
    [
      "https://g.alicdn.com/entry/boot.js",
      "data:text/javascript,console.log('boot stubbed');"
    ]
  ],
  "cors": [
    "127.0.0.1:9000",   // urlFilter：子串命中
    "*.mock.test"        // * 通配任意前缀子域
  ],
  "headers": [
    [
      "http://127.0.0.1:9000(/.*)?",
      { "X-Env": "local", "X-Debug": "1" }
    ]
  ]
}

10通过 JS 操作配置（自动化 / Agent）

在新标签页打开 chrome-extension://<插件ID>/XSwitch.html，页面会在 window 上暴露全局对象 xswitch。在 DevTools 控制台或自动化工具（Playwright、浏览器 MCP 等）中执行 JS 即可读取、修改配置：修改写入 chrome.storage.local 后，Service Worker 会立即重建 DNR 规则，当前页面的列表、编辑器与开关也会同步刷新。

// 总开关与选项状态：{ enabled, clearCacheEnabled, corsEnabled }
await xswitch.getState()

// 分组列表：名称、是否勾选、配置详情、JSON 错误
await xswitch.list()
// [{ id: '0', name: 'Current', active: true, pinnedAt: 0,
//    jsonc: '{...}', config: { proxy: [...] }, error: '' }]

// 按名称或 id 查询单个分组，不存在返回 null
await xswitch.get('Current')

// 新建分组（名称重复会报错），不传配置时初始为 {}
await xswitch.add('mock', { cors: ['m.api.com'] })

// 更新配置：传对象或 JSONC 字符串；格式非法直接抛错且不写入
await xswitch.set('Current', {
  proxy: [['https://cdn.example.com/(.*)', 'http://localhost:3000/$1']]
})
await xswitch.set('Current', '{ "proxy": [] }')

// 删除分组（同时清理该组配置与生效项）
await xswitch.remove('mock')

// 勾选/取消勾选分组
await xswitch.setActive('Current', false)

// 修改总开关与选项：getState() 的字段都支持，未传的保持不变
await xswitch.setState({ enabled: false })
await xswitch.setState({ corsEnabled: false })
方法说明返回
xswitch.list()列出全部分组数组，每项含 id、name、active、pinnedAt、jsonc、config、error
xswitch.get(nameOrId)按名称或 id 查询单个分组分组对象，不存在为 null
xswitch.add(name, config?)新建分组，名称重复时报错创建后的分组对象
xswitch.set(nameOrId, config)更新分组配置，config 可为对象或 JSONC 字符串更新后的分组对象
xswitch.remove(nameOrId)删除分组，并清理其配置与生效项被删除的分组对象
xswitch.setActive(nameOrId, active)勾选 / 取消勾选分组更新后的分组对象
xswitch.getState()读取总开关与选项状态{ enabled, clearCacheEnabled, corsEnabled }
xswitch.setState(state)按字段更新 getState() 的任意字段（enabled、clearCacheEnabled、corsEnabled），未传字段保持不变最新的 state
写操作（add / set）都会先校验 JSONC：格式有误时直接抛出错误，配置不会写入。分组是否生效由两层决定：该组 active 为 true，且 getState().enabled 同为 true；error 非空的分组不会生效。
请在新标签页打开该地址再操作；点击工具栏图标打开的弹出窗口失焦后会自动关闭，脚本随之中断。

11常见问题

Q1：规则保存了但没有生效？

依次检查：① 全局开关是否打开（图标应为蓝色）；② 该规则所在分组是否已勾选，只编辑未勾选的分组不会生效；③ 分组名旁是否有红色 !（该组 JSON 格式错误，规则不会生效，悬停可看原因）；④ 角标是否为红色 !（有规则被浏览器拒绝，见 Q2）；⑤ 浏览器可能缓存了旧资源，打开「禁用缓存」开关再强刷（⌘/Ctrl + Shift + R）。

Q2：角标显示红色 !，部分规则被跳过？

说明有规则被浏览器判定非法、未编译进 DNR（其余规则仍然生效）。常见原因：正则使用了 RE2 不支持的先行/后行断言（(?=、(?<!）等语法；proxy/headers 的模式无法整条匹配 URL。具体哪条被拒可在扩展的 Service Worker 控制台查看日志。

Q3：捕获组引用该写 $1 还是 \1？

按 $1、$2 写即可。DNR 原生使用 \1 语法，插件在编译规则时会自动完成 $N → \N 的转换。

Q4：转发命中了，但原 URL 的路径/参数丢了？

替换目标会整串重建新 URL，没有被捕获组引用的部分不会自动保留。把要保留的片段用 (.*) 捕获，例如 ["https://api.real.com/(.*)", "http://127.0.0.1:9000/$1"]。

Q5：cors 里写 (.*).b.com 这类正则为什么不命中？

cors 使用的是 URL 匹配模式（urlFilter），不是正则：URL 包含该子串即命中，* 为通配符，.、(、) 均按字面处理。匹配子域请直接写 *.b.com 或干脆写 b.com。

Q6：带凭据（withCredentials）的跨域请求仍被拦截？

Manifest V3 下插件只能注入固定响应头，Access-Control-Allow-Origin 恒为 *，浏览器规定凭据请求不允许 *。绕行方案：用 proxy 把接口转发到与页面同源或本地的地址。

Q7：转发到本地后出现混合内容/安全提示？

把本地目标写成 http://127.0.0.1:端口 而非 http://localhost:端口，Chrome 将 127.0.0.1 视为可信来源，不会拦截。

Q8：怎么把规则分享给团队？

「更多」菜单 →「导出配置」得到 JSON 文件；对方「导入配置」选择该文件即可。重名分组可选择覆盖或自动重命名（追加时间戳）。

Q9：同时安装/开启多个版本的 XSwitch，会冲突吗？

配置、分组勾选、开关状态、图标角标互不影响——存储和 DNR 规则 ID 都按扩展隔离，各版本读写的都是自己那份数据。真正会打架的是作用到网络上的规则：

  • 同一 URL 的 proxy 规则：两个版本都匹配时只会应用一条。按 Chrome 的规则，动作类型相同（都是重定向）时最近安装的扩展胜出，与规则自身的 priority 无关。表现为旧版本的规则「配了却没生效」，而角标数字照常显示。
  • cors / headers：修改不同的头可以叠加；修改同一个头（如 Access-Control-Allow-Origin）结果不确定，可能互相覆盖。
  • 快捷键 Ctrl/⌘ + Shift + X：浏览器级唯一，后安装的扩展会注册失败，可在 chrome://extensions/shortcuts 查看并改键。
  • 禁用缓存：清的是整个浏览器的缓存，不区分是哪个扩展触发的。

建议：做版本对比时把两个版本的匹配域名错开，不要覆盖同一批 URL；只是升级就从同一渠道覆盖安装（同一扩展 ID 会替换旧版），不要长期保留商店版 + 未打包版并存。排查「规则不生效」时，先确认 chrome://extensions 里是否还有另一个 XSwitch。
